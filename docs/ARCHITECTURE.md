# ARCTIS architecture

## Layers

```text
pages ──> feat ──> shared
   └──────────────> shared
```

| Layer              | Owns                                                    | Must not import                                                                           |
| ------------------ | ------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `src/pages/`       | route registration, thin composition                    | other pages (except `route.tsx` registration), feature internals beyond public components |
| `src/feat/<name>/` | feature UI, state, data, demos                          | other features, `pages/`                                                                  |
| `src/shared/`      | feature-independent primitives, registry source, tokens | `feat/`, `pages/`                                                                         |

The architecture validator in `.agents/skills/frontend/scripts/validate-architecture.mjs` is authoritative. ESLint/Oxlint and TypeScript are complementary checks.

## Routing

React Router data mode. `src/pages/route.tsx` assembles the root tree. Each route group owns a `route.tsx` and registers its own pages:

```text
src/pages/
├── route.tsx             root aggregator + /components redirects
├── home.tsx
├── not-found.tsx
└── docs/
    ├── route.tsx         docs shell: tabs + persistent sidebar
    ├── index.tsx         /docs (installation)
    ├── components.tsx    /docs/components
    ├── component.tsx     /docs/components/:name
    └── blocks.tsx        /docs/blocks
```

Pages are lazy-loaded at the route level. Demos are lazy-loaded per component, and Shiki is imported dynamically only when a code block renders.

## Registry flow

```text
src/shared/components/registry/*.tsx   source of truth
registry.json                          item metadata, targets, deps, CSS
public/r/*.json                        generated by shadcn build (gitignored)
dist/                                  static site + public assets
```

`pnpm build` runs `pnpm registry:build` (`shadcn build`) before `vp build`. The resulting static JSON is served at:

- `/r/registry.json`
- `/r/{name}.json`

Install path: shadcn CLI fetches an item, writes files to the consumer's configured `aliases.ui` / `aliases.lib`, rewrites the standard `@/lib/utils` import, and installs declared npm dependencies. No ARCTIS application aliases are involved.

## Styling

`src/shared/styles/globals.css` defines the design tokens for light and dark, maps them through Tailwind v4 `@theme inline`, and owns the shell layout variables (`--sidebar-width`, `--rail-width`, `--content-max`, `--gutter`). Surfaces are squared and layered (`.glass-panel`, `.surface-card`, `.shell`); radius tokens are `0`. Typography is a two-font system: Fraunces italic (`font-display`) for display emphasis and IBM Plex Mono (`font-mono`) for labels, metadata, and code, with system sans for body copy. See `docs/DESIGN-SYSTEM.md` for the layout, typography, button, badge, and surface specs. Type sizes come from the `text-*` scale tokens (`text-overline` through `text-display`). Composite classes (`type-display`, `type-page-title`, `type-section-title`, `type-eyebrow`) add weight, tracking, and wrapping; buttons and badges are specified once in `.btn` / `.btn-*` and the `Badge` primitive. Layout has no outer max width; `DocsShell` caps every docs page body with `.content-col` so components, blocks, and prose share one width. Registry components use standard shadcn token names (`background`, `foreground`, `border`, `card`, `accent`, etc.) so they inherit the consumer's theme.

## Static hosting

The app is an SPA. `vercel.json` and `public/_redirects` fall back to `index.html`; `VITE_BASE` supports subpath deployments. Registry JSON is static and cache-friendly.

## Limits

- No prerendering. Public pages are client-rendered with React 19 hoisted `<title>`/`<meta>`, a static sitemap, and robots.txt. Add prerendering if search visibility of interactive previews becomes critical.
- The architecture validator cannot prove that a page is thin or that `shared/` code is genuinely feature-independent. Review those semantically.
